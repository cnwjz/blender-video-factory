# BVF 人类协作规则

## 三方职责

| 角色 | 职责 | 禁止 |
|------|------|------|
| Claude Code | 确定性执行、量化证据、技术根因定位。可以报告 TECHNICAL_PASS 或 TECHNICAL_FAIL，无权宣布视觉通过、资产锁定、阶段通过或适合发布。 | 判断"好不好看"、替 GPT 说"通过"、自行扩大任务范围 |
| GPT | 技术复核、第一轮视觉审核、比较版本、指出可见问题与可能的技术原因 | 最终发布决定、最终止损 |
| 用户 | 最终视觉判断、发布决策、风格方向、止损、阶段批准、资产锁定 | — |

## 任务执行规则

1. 在统一 CLI 于 Phase 2 通过校准并由用户启用后，正式任务必须通过 Guard 执行。在启用前，项目工作保持暂停。
2. 直接绕过 Guard 的任务证据无效。证据链断裂时该轮结果无效。
3. 修改 locked_items 中列出的资产前必须获得用户明确批准。
4. 视觉质量与发布价值不能由代码自动批准。GPT 审核通过不等于用户通过。
5. 每轮结束 Claude Code 必须输出结构化结果（通过/未通过/新发现/建议）。

## 协议维护

6. 协议代码（protocol_guard/ 目录）的修改必须单独授权，不属于普通任务范围。
7. Claude Code 优先处理可代码化验证，GPT 优先处理视觉审核。
8. actor identity 目前属于约定式权限，尚未经过密码学或外部身份验证。
