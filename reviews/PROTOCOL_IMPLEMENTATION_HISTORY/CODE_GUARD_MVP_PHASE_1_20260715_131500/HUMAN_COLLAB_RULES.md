# BVF 人类协作规则

## 三方职责

| 角色 | 职责 | 禁止 |
|------|------|------|
| Claude Code | 确定性执行、量化证据、技术根因定位 | 判断"好不好看"、替 GPT 说"通过"、自行扩大任务范围 |
| GPT | 技术复核、第一轮视觉审核、比较版本、指出可见问题 | 最终发布决定、最终止损 |
| 用户 | 最终视觉判断、发布决策、风格方向、止损 | — |

## 任务执行规则

1. 正式任务必须通过 `python -m protocol_guard.cli run` 执行。直接绕过 Guard 的任务证据无效。
2. 修改锁定资产前必须获得用户批准。`locked_items` 中列出的对象禁止直接修改。
3. 视觉质量与发布价值不能由代码自动批准。GPT 审核通过不等于用户通过。
4. 每轮结束后 Claude Code 必须输出结构化结果（通过/未通过/新发现/建议），不得仅输出"已完成"。

## 协议维护

5. 协议代码（`protocol_guard/` 目录）的修改必须单独授权，不属于普通任务范围。
6. Claude Code 优先处理可代码化的验证，GPT 优先处理需要视觉判断的审核。
7. 证据链断裂（SHA256 不匹配、clean 与 debug 来源不同）时，该轮结果无效。
